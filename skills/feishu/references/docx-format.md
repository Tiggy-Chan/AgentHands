# 飞书 docx ↔ Markdown 语法对照（2026-09-10 实测）

skill 写飞书文档有两条路：**import**（服务端导入，GFM 由飞书转换）和 **replace**
（浏览器 text/html 剪贴板粘贴，本地 `_feishu/md_html.py` 转换）。本文档说明哪些
Markdown 语法能安全落到飞书文档，哪些有损——给"要写到飞书去的 md"当写作规范用。

## 安全（两条路都验证过，replace 为 HTML 粘贴实测）

| Markdown | 飞书块 | 备注 |
|---|---|---|
| `# ~ ######` 标题 | 标题 1-6 | |
| `**粗体**` `*斜体*` `~~删除~~` `` `code` `` | 行内样式 | 纯文本粘贴会丢斜体/删除线；HTML 粘贴正常 |
| `[文字](https://…)` / 裸 https URL | 链接 | 相对路径链接（`./xx.md`）降级为纯文字 |
| 管道表格 | 真表格块 | HTML 必须仿飞书自身 ace-table 形状（`class="ace-table"` + colgroup + ace-line 单元格），裸 `<table>` 会被整个丢弃 |
| ```` ```lang ```` 围栏代码 | 代码块 | 语言标签保留（导出时首字母大写）；建议小写 |
| `-`/`1.` 列表、两层以上嵌套 | 无序/有序列表 | |
| `- [ ]` / `- [x]` | 待办事项 | ✅ 实测两种粘贴都能转成待办块 |
| `> 引用` | 引用块 | 多行引用会合并成一段 |
| `---` | 分割线 | 文件**开头**的 `---` 是 frontmatter，见下 |

## 有损（会变形但不丢正文）

| 构造 | 行为 |
|---|---|
| YAML frontmatter | **import 不识别**：`---` 变分割线、`title:` 变二级标题。**replace 会剥离**。写到飞书的 md 不要带 frontmatter |
| `![alt](url)` 图片 | replace 降级为 `[图片:alt]` 占位文字；import 对**远程 URL** 会抓取转存（实测），本地路径不行 |
| 表格单元格内的 `|` | 必须 `\|` 转义或包进 `` `code` ``，否则列错位 |
| 多行段落 | 软换行合并为一行（GFM 语义） |

## 不支持（原样变纯文本或直接消失）

- 脚注 `[^1]`、定义列表、嵌入 HTML 块（replace 一律转义，import 行为未测——别用）
- 数学公式 `$…$`、Mermaid 围栏（变普通代码块，不渲染）

## 面向飞书的 md 写作规则

1. 不要 frontmatter；文档标题用 `#` 一级标题或靠文档名。
2. 表格/代码围栏前后各留一个空行。
3. 代码围栏语言标签小写（```python / ```bash），未知语言留空。
4. 列表嵌套每层缩进 2 空格，别超过 3 层。
5. 表格单元格内的竖线写 `\|`。
6. 图片尽量用可公开访问的 URL；本地图片目前无法随文上传。
7. 写完用 `doc <token>` 读回检查；`doc replace` 自带 verified 校验
   （逐行包含核对 + 表格/代码构造核对），`verified=false` 时看 `missing_line_samples`。

## 编辑器行为备忘（实测）

- 编辑器 innerText 里混有页头控件文字（添加图标/添加封面/展示文档信息）和零宽空格，
  判空必须剔除（documents.py `_EDITOR_CHROME`）。
- Ctrl+A 需连按多次才扩到全文，且扩展是异步的——清场要循环验证。
- 粘贴可能弹「保留格式/纯文本」选择框；replace 会自动按 Enter+Escape。
- 服务端保存有防抖，导出校验要轮询（最多 5×2s）。
- 服务端 markdown 导出失败时的 DOM 降级会丢全部结构，输出带
  `<!-- feishu:export-fallback … -->` 标记；`doc --strict` 可禁止降级。
